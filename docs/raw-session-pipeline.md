# 原始会话重建流程

调用方提供完整 JSONL、物理行号和已知 `domain`。`raw-run` 不读取筛选结论，不判断样本值不值得重建，不推断领域，不改写或脱敏原始数据。

## 重建到什么程度

交付目标是：保留原用户任务的语义，恢复该任务开始时的必要状态，使解题者仅凭交付的任务、环境和允许的工具，就能完成原要求。原机的无关部分不要求复刻；与任务有关的行为、资料、接口和限制必须保留。恢复了多少文件、通过多少格式检查、是否启动 rollout，都不能单独证明达到这个目标。

以下是重建完成的标准，不是已经全部实现的自动检查，也不是原始样本筛选 rubric。逐项核对发现的缺口用于恢复环境或明确待补信息，不用于删掉原任务要求。

| 核对对象 | 必须恢复的内容 | 完成依据 |
| --- | --- | --- |
| 任务 | 目标、对象、时间与版本、指定资料、输入条件、输出、用户修正及适用约束 | 与原始用户和相关系统消息逐项对应，既不丢要求，也不把原助手行动变成新要求 |
| 任务起点 | 当前请求前已存在的文件、数据、配置、会话状态与已完成的先前工作 | 按观察与修改的先后关系核对；不能混用 session 最早状态与当前任务解决后的状态 |
| 必要环境 | 求解实际需要的资料、接口、依赖、工具能力和可观察行为 | 在最终交付环境实际读取或调用；所需资料可达且足以支持相关要求 |
| 原始信息的利用 | 系统提示、工具定义、用户与助手历史、调用参数、返回、错误、补丁、版本及子轨迹 | 重建者能访问完整原文；相关材料交付到环境或明确记录用途与缺口，不能在筛选引用时无说明丢失 |
| 任务仍待解决 | 原用户要修的缺陷、要新增的功能或要得出的分析仍留给 solver | 初态不包含本任务的参考解、最终答案或作者对待判断问题的结论；已有源码和原始资料正常保留 |
| 可解性 | 存在满足完整原要求的求解路径 | 在干净环境仅用交付输入与允许工具完成并核对；检查者可以读原轨迹审查忠实性，但求解过程中不能补入私有原轨迹或未交付文件 |

一个 solver 失败不证明无解，一个 solver 声称完成也不证明可解。文件行为用与原要求对应的实际输入输出和测试核对；分析回答用所交付的原始资料逐项核对事实与引用。人工在包外补读资料后改好的答案，不能作为该包可解的证明。

### 完整利用轨迹与初态的关系

重建者可以利用整个 session，包括当前任务之后的轨迹。后续读取可以证明未修改的初始文件内容，首次修改的补丁删除侧可以恢复修改前正文，报错和调用参数可以揭示接口、配置或缺失依赖；都须核对中间写入及来源。后续修复的新增侧和最终答案属于参考材料，不预置到本任务初态。

历史助手内容按用途处理。若下一任务要求“按刚才的方案实现”，该方案中实际被依赖的步骤、参数、接口及约定就是下一任务输入，不能只留下方案名称。若任务要求核实历史结论，则保留原结论并标明待核实；不能提升为事实。原助手答案中的链接和检索词可以帮助恢复来源，不能冒充已捕获的页面正文。

真正澄清同一目标的后续消息可以合并。依赖前一产物而提出新目标的请求，应明确任务依赖与新的起点；尤其不能仅用“最后一条用户消息之前”划分输入和答案。工具失败、未返回和不存在是不同状态。截图、附件、子 agent 输出或外部服务状态只有实际捕获到的部分才能作为事实，未知部分显式记录。

### 两类环境的充分性

search 需要恢复可检索的语料和必要历史，包括正文、来源、时间、版本、检索范围及分页/行号等信息。完整原始捕获优先保留；实时检索可补充公开缺口，但不能替代未取得的指定年份资料或私有代码。成功搜索一次或打开一页，只证明该次访问可用。代码检索可以用忠实的源码语料与检索工具完成；用户要求修改或执行的任务还需要对应可操作环境。原工具名称可以适配，查询、读取、分页、引用和任务所依赖的行为不能丢。

terminal 需要恢复任务相关的目录、源码、配置、数据、依赖和已有行为。必要入口须在交付环境运行，原有持久化与重试等行为须按任务需要保留，用户要修的错误仍应存在。补全优先拼接原始观察，再利用修改前片段、历史版本和已观察接口恢复缺口；必要推断单独记录，不另写一个相似项目。若任务依赖真实账户或动态服务状态而原文未捕获，受控替身只能证明已覆盖的本地协议与行为，不能代替真实外部结果。

实际调试围绕一条对应关系展开：**原要求 → 必要输入或能力 → 原始证据 → 交付位置 → 实际求解结果或具体缺口**。先查信息有没有传到下一阶段，再查状态与工具行为，最后判断失败属于重建、解题还是基础设施。当前实现与真实缺口见 [当前状态](current-status.md)。

## 共用输入

1. 冻结原始行与 SHA256。任务分段模型将用户请求、继续和纠正绑定到对应任务，保留原始消息索引。
2. 模型理解完整 session 的系统消息、工具协议、调用时序和意图。harness 提醒和用户请求可能在同一条消息，不能按前缀整条过滤。原文与机械索引一并提供；内容引用仍从原始返回中提取，引用错误带具体位置返回模型。
3. Intent 恢复用户目标及可观察的验收义务。一个 session 的多个任务分别处理，以各自开始前的状态为初态。

### harness 适配的边界

结构层处理消息、调用 ID、返回槽位、原始索引与待返回状态，并标注已识别的截断包装和连续显示行号范围，让不同外壳都能指向同一份原文；它不靠工具名判断读写、任务意图或执行成功。模型同时读取完整系统消息、工具定义、参数、返回和前后文，解释包装调用、子 agent、异步句柄与读写影响。系统声明不一定与实际返回一致，两者都保留；用户正文中的 harness 提醒也不改成 system 角色。

文件正文由模型给出原始引用，再按引用精确提取，模型不重写正文。当前工作区观察参与初态回放；外部路径、临时克隆和历史版本保留为有来源的参考，不自动物化。原文和两类观察都会传给补全阶段。缺失的子轨迹、已截断的返回和未完成调用只能标明未知，不能由适配器或模型补造。

解析契约 v1.8 分别记录参数请求的动作和实际返回的观察，并向下游保留内部执行关系。每个被引用为文件的返回文本，须由正文与明确起止行的排除片段完整、无重叠地覆盖；排除须说明原文依据。请求行范围与正文冲突时先核对原始参数，已引用的连续编号正文不能部分改称包装。以截断为由排除的行须包含声明的原文标记，不能连带丢弃相邻源码。覆盖冲突指派生 JSON 的范围错误，不代表原文受损。这些校验仍不能替模型证明每段的语义分类正确，真实产物必须对照原文核查。

当前 DeepSeek 使用完整输入和 1M 上下文配置；输出预算为 128K。真实运行曾在约 35 万输入 token 时耗尽原 64K 输出预算，正文仅完成部分事件：大上下文不等于足够的推理与输出预算。截断返回保留为调用错误，不能当作语义拒收或不完整 JSON 继续回放。

结构覆盖和引用合法不等于语义完全正确。真实样本审核需要进一步对照调用意图、返回的实际内容、文件版本与时序。当前 R01/R04 全量结构盘点只发现 `assistant.tool_calls` 加 `role=tool` 的外壳；工具名称和系统协议有多种。暂不按产品名称重复建立适配器；出现新的真实消息外壳时再增加结构适配，并保留无法解释的原始数据。

## 两种 domain

| 阶段 | search | terminal |
| --- | --- | --- |
| 环境 | 任务上下文、历史检索捕获及可用检索工具 | 从原轨迹恢复文件观察，补全必要源码、配置和依赖 |
| 作者检查 | 根据任务实际读取本地语料，或查询并读取公开网页 | 在 AGS 中执行原有入口，核对返回值、文件和重复运行 |
| 环境检查 | 检查所需证据访问和引用回执；没有独立的回答内容验收 | 独立模型检查初态是否支持任务，以及 load/reset/dependency 执行证据 |
| 验证器 | 不编造文件测试；回答内容保留独立核查状态 | 生成 FILE 行为测试与完整参考解，独立审查后执行 RED 校准 |
| rollout | 真实模型查询交付的语料；需要时使用网页工具 | 真实模型在冻结 Harbor 任务包中执行 |

search 指检索与证据综合，工具不一定是网页搜索，也可能检索代码库或其他资料。补全模型根据原任务说明 `requires_live_web`；代码比较任务实际读取交付语料即可，不要求联网。若缺少完成原任务必需的私有源码，仍须明确列出缺口，不能靠公开网页替代，也不能改判为 terminal。R01 第559条用于验证这一分支，实测状态见当前状态页。

Intent 的验收义务保留原请求的时间、指定来源、比较对象和数据条件；无法核实不等于可以删去。意图提取角色本身的“不得联网”等运行限制不复制成原用户约束，只读任务也不自动增加“禁止运行测试”。

terminal 作者保留完整会话和阶段历史，负责初态、自测、隐藏测试和参考解；独立检查使用新会话。原用户要求修复的缺陷留给 solver，原有正常行为应可用。完整循环、停止条件及执行边界见 [研究者管线](researcher-pipeline.md)。

验证器校准检查初态应失败、两份独立参考解应通过、错误实现应失败。测试须复现原错误的输入或返回形态；应用层错误不能换成同名网络异常。校准数值通过仍须检查真实 rollout 产物是否合理。

## 输出与状态

先看各自最终清单中的任务和停止原因：terminal 为 `reconstruction_manifest.json`，search 为 `manifest.json`，再依次读取任务、候选工作区、环境执行回执、验证器校准和 rollout。原始失败、反馈、请求和响应分别保留，不回写旧结果。

terminal 交付的 Harbor 包包含任务说明、初始工作区、环境声明以及仅供验收端使用的参考解和测试。solver 只能看到任务与公开初态。实际轨迹、工作区输出、评分和清理回执保存于独立 trial。

`READY` 只描述对应阶段。`ROLLOUT_COMPLETED` 只说明执行完整。自由文本内容未核查时保留 `NOT_ASSESSED`；人工核查模式下的未验证义务不能变成自动通过或 SFT 资格。

## 批处理

`prepare_session_batch.py` 冻结输入并核对覆盖；这不表示样本已经完成重建。`run_session_batch.py` 接收同一 domain 的清单和显式 `--domain`，逐条处理。缺少最终重建清单、失败、超时和未完成状态分别记录，保留原始日志。批次完成不等于其中每条成功。

实际输入、版本和当前结果统一见 [当前状态](current-status.md)；历史运行保留在 Git 历史和产物归档中。
