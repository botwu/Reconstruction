## 3. 需要评审决定

- **终态交叉核对的对象**：规格 §4 步 4 写"capture 末个 turn 的派生结果"与 `CaptureQualityV2.terminal_status` 核对；实现核对的是观测窗内序号最大的 `ASSISTANT_MESSAGE`（`validation.py:941-948`）。当 capture 末尾是 USER-only turn（无 assistant）时两者分叉。M1B 的 `_terminal_status(messages[-1])` 恒以最后一条消息（验证为 assistant）为准，所以实现路径与 M1B oracle 一致，是规格措辞不精确。建议改规格。
- **配对索引末写覆盖**：`result_by_call`/`call_by_result` 用 dict 赋值（`builder.py:180-184`），同一 `matched_call_event_id` 重复时静默取最后一条。M1B 契约下不可能重复（每个 TOOL_CALL 事件恰一个 `tool_call_id`，matched 要求 1:1），且 reader 已先跑 `validate_compiled_run`。可接受；若要 fail-closed 可加一个 tripwire 断言。
- **空观测流**（capture 全部事件在前缀）：产 0 turn、0 edge、1 条 accounting。与形态甲"单终止 capture 仍产 PREFIX_ROOTED 回合"不同——但 M1B 保证每 capture 至少一个 boundary、终止 assistant 必在观测窗，所以空观测流在合法 M1B 输入上不可达。建议加一个防御性测试固定该行为即可。
