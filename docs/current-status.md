## 重建框架和各模块预期

完整 session → 任务边界与语义解析 → 按 domain 恢复初态 → 独立充分性检查 → Harbor 交付与真实求解 → 按失败原因反馈。

| 模块 | 预期产物与核查 |
| --- | --- |
| 原文与工具解析 | 原始 system、工具定义、参数、返回、错误、补丁、历史及子 agent 输出完整保留；派生解释带原文坐标，引用逐值可核对 |
| 任务提取 | 忠实恢复用户目标及必要上下文；原助手选择的文件名、方案和通用工作流不自动成为用户验收要求 |
| terminal 初态 | 恢复任务开始时的源码、依赖、数据及执行条件；原待修问题仍存在，目标实现未预装；实际检查模块来源和非空业务链 |
| search 环境 | 交付原始捕获与真实补充资料、版本、读取范围和必要检索能力；片段、题录、摘要、全文、OCR 明确区分 |
| 独立充分性 | 检查任务在当前环境是否可解、恢复是否忠实；将任务原缺陷、重建缺口和无关问题分开，不把 import 成功当成正文完整 |
| 文件验证与 rollout | 行为测试和独立文件语义审查共同校准未改初态、两参考解及错误变体，再核实际 solver；捕获与文件哈希完整不代表回答内容正确 |

harness（Codex、Hermes、Claude Code 等）解释工具协议；domain（search、terminal）决定恢复策略。timeline 用于来源、时序和保守初态种子，不能机械执行旧命令或替模型决定全部语义。

重建者首次请求直接包含完整 SOURCE_SESSION，后续同一研究者会话保留来源并接收真实反馈。原文存在或能读取并不代表已经利用，需要检查实际读取、文件来源、恢复差异与执行结果。只读参考仓库 AgenticFoundry 不作为运行依赖，也不修改。
