## 当前框架

完整 session → 任务分段与模型语义解析 → 任务要求和起点 → 按 domain 恢复环境 → Harbor 交付 → 真实 solver → 按具体失败归属反馈。

- 重建者首次补全请求直接收到全部原消息和顶层字段；派生索引帮助定位，不能代替原文。system prompt、工具定义、参数、返回、报错、补丁、历史回答和子轨迹都可作为恢复依据。
- timeline 用于核对来源、调用顺序和读写状态，不机械执行旧命令。初态以该任务第一条用户请求为起点；同任务的最终答案只供重建参考。独立后续任务真正依赖的历史方案应作为输入恢复。
- search 恢复历史、原始返回、证据语料和检索能力，沿原轨迹线索获取真实页面、论文或对应版本的源码。terminal 恢复文件初态、依赖和运行行为，执行实际探针并校准验证器。
- harness 决定如何解释系统提示、工具协议和消息结构，domain 决定环境恢复策略；不按工具名称猜领域。
- solver 只接收任务、交付环境和允许的工具。核查根据 solver 当时实际收到的完整返回判断引用，不能借补全者已经读到的全文证明 solver 读过。
- 有实证的环境缺口反馈给补全者；solver 的事实错误、服务故障和核查证据缺失分别记录。不能借返修向初态写入答案。

模块与契约见[重建源码地图](rebuild-live-map.md)和[原始会话流程](raw-session-pipeline.md)。AgenticFoundry 仅作只读参考，本项目不依赖其本地目录。

## 本轮源头修复

1. **完整原文交接。** 之前作者主要依赖派生信息或读取入口，不能保证完整 session 已进入首次请求。search 与 terminal 现在共用完整原文输入；消息外层保留原始索引，内层和顶层字段不删减。重复派生源码正文改为原文定位，不再叠加相同内容。
2. **核查绑定实际返回。** 之前 reviewer 只收到512字符预览，可能把来源存在、作者读过或页面全文可达误当成 solver 已读取。现在逐条绑定真实调用ID、参数、状态和完整返回，并重算正文哈希；缺失、截断或冲突记为 REVIEW_INCOMPLETE，不误判环境缺口。
3. **去掉错误的重复读取要求。** 本次 live run 首轮已包含5条完整原返回，旧门禁仍错误要求重复读取其中4条。已按原消息索引、调用ID和正文一致性确认实际供给。用首轮真实模型输出与原网页缓存重放，修复后一次通过，零新模型/网络请求；不把原文已供给等同于模型语义已正确理解。
4. **识别验证器没有实际修改。** R04:1第4–6轮测试、oracle、mutation与覆盖契约相同，只有说明或提示哈希变化。现在语义拒绝后若实际程序未改，返回 VERIFIER_NO_PROGRESS 和原具体反例，避免再次独立审查同一候选；程序修改后继续迭代。此修复已对真实旧产物和回归验证，不代表新的terminal闭环已通过。
