## 框架与模块预期

完整 session → 语义解析与任务起点 → 按 domain 恢复环境 → 环境充分性验证 → Harbor 交付与真实 solver → 按失败原因反馈给相应模块。

| 模块 | 应交付什么 | 实际检查方式 |
| --- | --- | --- |
| 原文与解析 | 完整 system prompt、工具协议、参数、返回、报错、补丁、历史及子 agent 输出；有原文定位的解析结果 | 比较原文哈希、逐值核对消息和顶层字段；检查调用与返回配对，保留未返回调用 |
| 任务边界 | 原任务要求、初态起点、真正依赖的历史输入 | 区分历史输入和同任务最终答案；不向 solver 预填待分析结论 |
| search 环境 | 原始返回、真实页面或源码、来源与读取范围、可用检索能力 | 检查资料是否支撑原任务；页面可达、摘要可读、全文可读分别记录 |
| terminal 环境 | 初态文件、锁定依赖、执行条件 | 检查原有行不变、补全来源、实际加载文件路径及真实行为，不能只看 import 成功 |
| 文件验证器 | 对任务要求有效、不过度限定实现的判定 | 独立语义审查、RED 反例与实际执行；已有缺陷单独交付，不任意扩大任务 |
| 原生 Harbor | 冻结任务包、模型配置引用、真实请求/响应/工具/产物 | 对账实际调用与完整答卷，确认沙箱清理；捕获不完整不得冒充通过 |
| 内容复核 | 按任务要求判断支持、solver 错误或环境缺口 | 基于 solver 当时实际收到的完整返回；只有环境缺口进入补全循环 |

harness（Codex、Hermes、Claude Code 等）决定如何理解会话结构和工具协议；domain（search、terminal）决定恢复策略。timeline 用来核对来源及先后状态，不机械重放旧命令。模型首次补全请求接收完整原文，索引不能替代原文；原文存着不等于后续实际利用正确。

AgenticFoundry 仅作只读参考，本项目不依赖其本地目录。实现地图见[重建源码地图](rebuild-live-map.md)、[原始会话流程](raw-session-pipeline.md)、[Harbor 交付](harbor-task-delivery.md)。
