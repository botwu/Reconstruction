## 重建框架与模块预期

完整 session → 任务边界与语义解析 → 按 domain 恢复初态 → 充分性检查 → Harbor 交付与真实求解 → 按失败原因反馈。

| 模块 | 应交付什么 | 实际检查 |
| --- | --- | --- |
| 原文与解析 | 完整 system prompt、工具定义、参数、返回、错误、补丁、历史及子 agent 输出，带原文定位 | 原文哈希、消息和顶层字段逐值核对；调用配对，保留未返回调用 |
| 任务边界 | 原用户要求、初态起点、必要历史输入 | 前置方案可以是输入；同任务答案和解题后状态不能预置 |
| search 环境 | 原始返回、真实补充来源、读取范围、所需检索能力 | 来源确实交付且足以支撑任务；区分片段、摘要、相关章节和全文 |
| terminal 环境 | 初态文件、依赖、数据与执行条件 | 原始观察和版本来源对账；真实加载路径、非空输入和任务相关行为 |
| 文件验收 | 行为保护与文件义务的有效判定 | 行为 pytest 加独立源码审查；同一标准检查初态、两参考解、错误变体和 solver |
| Harbor 与内容核查 | 冻结任务包、完整实际轨迹、产物与清理回执 | 核对实际请求、工具返回、答卷及源码；执行完成不等于内容通过 |

harness（Codex、Hermes、Claude Code 等）用于理解原工具协议；domain（search、terminal）决定恢复策略。timeline 用来核对来源与先后状态，不机械重放旧命令。补全首次请求直接包含完整 SOURCE_SESSION；索引、摘要和“原文可读取”都不能替代实际利用。

search 恢复资料与研究能力，允许 agent 沿公开线索抓取真实内容；terminal 恢复任务开始时的代码和执行环境，可以利用后续补丁的旧侧还原初态，但不能把修复新侧预装。AgenticFoundry 保持只读参考。
