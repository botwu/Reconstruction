## 目标与流程

最大限度利用完整原始 session，重建忠实的任务及对应可解初态，交付标准 Harbor 包，再用真实求解检查环境是否足够。**环境可用、执行完成、答案正确分别记录；不能靠缩小原任务或预填历史答案换取通过。**

system prompt、工具定义、参数、返回、报错、补丁、历史回答及子 agent 输出保留来源与时序。已采纳的历史方案可以成为后续任务的输入，本次待求解的旧答案和目标实现不能提前交给 solver。

- **search：**完整轨迹 → 意图与来源边界 → 轨迹恢复和必要的真实检索 → 材料覆盖检查 → Harbor → 两次原生求解 → 逐项后审。
- **terminal：**完整轨迹 → 意图及初态/产物绑定 → 文件、依赖与必要业务能力恢复 → 原入口/已有行为检查 → Harbor → 两次原生求解 → 原候选复核与反馈。
- domain 由调用方指定；Codex、Hermes、Claude Code 等 harness 影响协议解释。timeline 用于溯源，不机械重放旧命令；回答型任务仍可能需要源码等初态资料。
- 真实环境缺口返修补全；有原文依据的任务合同错误返回意图恢复；solver 错误不改初态。默认无固定返修轮数，保留显式上限及 NO_PROGRESS。服务故障、捕获不完整不能冒充资料缺失。
