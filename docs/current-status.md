## 自动反馈如何工作

完整原文 → 任务边界与工具语义 → 初态恢复 → 原入口和已有行为实跑 → 独立充分性检查 → Harbor → 真实求解 → 逐项后审。

- 后审重新认证每个 trial，读取完整对话、工具输出、初态和终态；每项结论必须引用该次实际证据。
- 仅发现 solver 错误时保留答卷及错误归属，初态不变。
- 疑似环境缺口交给不持有 solver 终态代码的新会话，复查原候选。确认了必要输入缺失、实际执行失败或重建损坏，才交回原作者返修。
- 返修后重新检查、导出、求解和后审；默认没有固定返修轮数，候选和诊断均未变化时停止为 NO_PROGRESS。
- 后审遗漏、引用无效、证据损坏或模型未完成时保留 REVIEW，不静默宣称闭环成功。

真实 R04:1、R04:2179 及 v20 接续已验证“读实际输出 → 识别答卷问题 → 不误修环境”这一分支。确认缺口后的编排及初态隔离另有针对性检查；不将模拟检查冒称额外真实缺口返修样本。

domain 由调用方指定。search 恢复证据语料、历史与检索能力；terminal 恢复任务起点的文件、依赖及业务能力。Codex、Hermes、Claude Code 等 harness 只决定工具协议解释，不复制成多条重建管线。timeline 保留来源与时序，模型结合完整原文解释和补全，不机械执行旧命令。
