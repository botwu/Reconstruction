## 重建框架与模块预期

完整 session → 任务边界与语义解析 → 按 domain 恢复初态 → 充分性检查 → Harbor 交付与真实求解 → 按失败原因反馈。

| 模块 | 预期产物及检查 |
| --- | --- |
| 原文与工具解析 | system、工具定义、参数、返回、报错、补丁、历史回答和子 agent 输出完整保留；派生解释引用原文位置，逐值可核对 |
| 任务提取 | 恢复用户目标与必要上下文；原助手选择的文件名和实现方案不自动变成用户要求 |
| terminal 初态 | 恢复源码、依赖、数据和执行条件；原待修问题仍存在，目标实现未预装；实际运行业务链并核对模块来源 |
| search 环境 | 交付原捕获、真实补充资料及所需检索能力；片段、题录、摘要、全文、OCR 分开记录，保留来源和版本边界 |
| 充分性检查 | 核对任务是否可解、恢复是否忠实；区分原任务缺陷、重建缺口与无关问题 |
| 文件验证 | 基于原要求及真实观察制定行为检查，用未改初态、不同合理参考解与错误变体实际校准；附加要求须有依据 |
| rollout 与反馈 | 核实际初态、完整请求/工具返回、输出文件和答案内容；缺环境交回 researcher，solver 错误不能靠改写环境掩盖 |

harness（Codex、Hermes、Claude Code 等）决定工具协议解释，domain（search、terminal）决定恢复策略。timeline 用于来源、时序和保守初态种子，不机械执行旧命令，也不替模型决定全部语义。

重建者首次请求直接包含完整 SOURCE_SESSION，之后同一会话接收真实反馈。原文存在或可读取不等于已经利用，必须核实际读取、来源、恢复差异和执行结果。AgenticFoundry 仅作只读参考，不作为运行依赖。
